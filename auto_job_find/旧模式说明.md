# 旧的自动化模式（write_response.py）

> 这是原项目的 Selenium 路线在本分支的**轻量版**用法，属于**备选方案**，不推荐。
> 推荐路线见根目录 README 的《用法》一节。那条路线在你已登录的真实浏览器里跑，
> 没有 webdriver 指纹，被封控的风险低得多。

## 和原版的区别

原版依赖 langchain + FAISS + torch（约 2GB，且要求 Python ≤ 3.11），本分支已改为**轻量方案**：
直接把整份简历文本交给大模型，不做向量检索。依赖只剩 4 个包：

```
openai
selenium
pypdf
python-dotenv
```

因此也**兼容 Python 3.13**。

## 运行步骤

1. 复制配置模板并填入自己的信息：

   ```bash
   cd auto_job_find
   cp .env.example .env
   ```

   至少填 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`、`CANDIDATE_NAME`、`CANDIDATE_CONTACT`。
   换中转 API 只要改 base_url 和 model 两行。

2. 把自己的 PDF 简历放进 `auto_job_find/resume/`。
   目录里原有的那份是仓库自带样本，**不是你的**。

3. 先保持 `DRY_RUN=1` 试跑，只看生成的打招呼语满不满意：

   ```bash
   cd auto_job_find
   python write_response.py     # 或双击 run.bat
   ```

4. 满意后把 `DRY_RUN` 改成 `0`。程序会启动 Chrome → 扫码登录 BOSS 直聘 → 自动逐个投递。

5. 每次运行的投递记录在 `auto_job_find/logs/` 下。

## 调整话术口吻

编辑 `auto_job_find/prompts.py` 里的 `LETTER_SYSTEM_PROMPT` / `LETTER_USER_TEMPLATE`。

## 关于 assistant 模式

原版会自动创建一个 OpenAI assistant，并在本地生成一个 `.json` 文件，只在首次运行时产生，
之后检测到该文件就复用已有的 assistant。相关说明见原项目 README。

## 风险提示

这条路线的本质是**驱动浏览器**，会反复开关窗口、带 webdriver 特征。
BOSS 直聘风控较强，`DRY_RUN=0` 批量投递有触发安全验证的风险，请自行判断。
若只是想省事，用油猴助手那条路线即可。
