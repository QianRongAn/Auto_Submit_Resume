# 油猴助手使用说明（BOSS 直聘 + LinkedIn）

这套东西解决的是什么问题：**在你真实的浏览器里自动筛岗位、写话术、投出去**，
不另开浏览器、不驱动浏览器，所以没有 webdriver 指纹，也就没有你之前遇到的那些
「窗口反复开关」「安全验证」。

两条使用路线：

- **全自动**（推荐）：在岗位列表页点一下绿按钮，剩下的它自己跑，逐张卡片读 JD、
  判断值不值得投、值得就生成一条定制话术并投出去。**筛和投都不需要你操作。**
- **手动单条**：你自己点开一个岗位，让它写话术、填进去，你自己按发送。

---

## 一、安装（只做一次，约 3 分钟）

### 1. 给 Edge 装油猴插件

- 打开 Edge，访问 <https://microsoftedge.microsoft.com/addons/detail/iikmkjmpaadaobahmlepeloendndfphd>
  （这是 Tampermonkey／篡改猴官方页），点「获取」安装。
- 如果打不开，用 Chrome 也行：<https://chromewebstore.google.com/detail/tampermonkey/dhdgffkkebhmkfjojejmpbldmpobfkfo>
- 安装后**要打开浏览器的「开发人员模式」**（新版油猴需要）：
  Edge → `edge://extensions` → 左下角「开发人员模式」打开。

### 2. 导入脚本

- 点浏览器右上角油猴图标 → 「添加新脚本」
- 把 `auto_job_find/boss_ai_helper.user.js` 的全部内容粘贴进去，覆盖模板
- `Ctrl+S` 保存

### 3. 启动本地服务

双击：

```
auto_job_find/start_ai_server.bat
```

**这个黑窗口要保持开着**（它同时是筛选引擎和话术引擎）。
验证：浏览器打开 <http://127.0.0.1:8765/health>，看到 `"ok": true` 就成了，
里面还会带上当前的筛选阈值和硬排除词数量。

## 二、全自动怎么用（推荐）

1. 正常登录平台，**进到岗位搜索结果页**
   - BOSS：`/web/geek/jobs?...`（左栏一排岗位卡片）
   - LinkedIn：职位搜索页 `/jobs/search/...`（左栏一排岗位卡片）
2. 右上角面板顶部小圆点是**绿色**（说明本地服务在跑）
3. 先点 **◐ 先演练一遍**，它只读 JD、只判断、不投递，
   日志区会一行一行告诉你「哪个岗位多少分、判定是什么、为什么」
4. 看没问题了，再点 **▶ 一键自动：筛完就投**
5. 中途想停：点 **■ 停止**（等当前这条走完就停）

跑完面板会汇总：`扫 N ｜ 投 N ｜ 跳过 N ｜ 待人工 N ｜ 失败 N`，
并把同样的摘要复制到剪贴板。

### 它会怎么判断该不该投

打分引擎在 `auto_job_find/matcher.py`，规则是**可解释**的，每条判定都有理由：

| 维度 | 怎么算 |
|---|---|
| 核心技能命中 | 方向词表（`CORE_TERMS`，按自己的求职方向改）命中即加分，命中的词在**标题**里权重翻倍 |
| 职位名强化 | 标题里直接写着方向词、或「数据科学/研究员」等，额外加权 |
| 硬排除 | 销售、保险、中介、招生、客服、服务员、司机、会计、行政、教师… 命中直接 0 分 |
| 资历过高 | 「首席/总监/principal/head of」重扣；JD 里写「要求 N 年经验」，按 N 与自己 `PROFILE["years"]` 的差距分档扣分 |
| 学历 | 明确要求博士（且不是「博士优先」）→ 扣分 |
| 签证 | `NEED_VISA=1` 时，写明「不提供签证赞助 / 需本地工作许可」的岗位重扣；写明「提供赞助/搬迁支持」的加分 |
| 目标区域 | 配了 `TARGET_REGIONS` 时，地点不在区域内 → 扣分（默认不配 = 不限） |
| 猎头含糊 | 标题/公司含「猎头、代招、外包、驻场、派遣」→ 扣分 |
| INCLUDE 门槛 | `INCLUDE_KEYWORDS` 非空时，一个都没命中 → 重扣 |

分数 ≥ 阈值（默认 60）判 **apply**；阈值以下 25 分内判 **review**（边界），
更低判 **skip**。

**边界分才会问一次大模型复核**（规则吃不准的岗位），避免每条岗位都烧 token。
模型给 `veto` 或低于 40 分就降成跳过，高于 70 分就升成投递。

**重要的一个坑（已经踩过并修好）**：硬排除词**只看岗位标题和公司名，不看 JD 正文、
也不看卡片全文**。原因是 BOSS 的岗位卡片尾部挂着福利标签，像「培训」「五险一金」
这类字样。拿卡片全文去匹配，一个正经的研发岗会因为福利描述里出现「培训」
被判成销售类岗位跳过。

### 它不会替你做的事（安全阀）

- 撞上**安全验证页** → 立刻停
- 到**每日上限** → 停
- LinkedIn 表单里的**签证 / 工作许可 / 国籍**类必填问题：
  - 你在 `.env` 里填了真实资质且 `AUTO_ANSWER_SCREENING=1`（默认开）时，脚本**照实勾选**
    已知项：「需要赞助」→ 勾 **Yes**、「已有当地工作授权」→ 勾 **No**（注明需赞助）、
    「国籍」→ 填你写的国籍。这些是事实，不是它替你编的
  - **凡是它没有标准答案的**（比如「描述你的签证状态」这种自由文本框）→ 一律退回
    「待人工」，**绝不把求职信糊进去冒充答案**，这一点有专门的自测锁死
  - `AUTO_ANSWER_SCREENING=0` 时，全部这类问题退回人工（最保守、最慢）
- LinkedIn 岗位跳转**公司官网申请** → 退回人工
- 已经投过的岗位（**跨天、跨页面记着**）→ 跳过

## 三、手动单条怎么用

### BOSS

1. 点开一个岗位，让右侧详情显示出来
2. 面板场景选「BOSS 招呼语（中文）」
3. 点 **① 生成本条话术** → 会自动点「立即沟通」、把话术填进聊天框
4. 模式选「逐条确认」的话，你自己按回车；选「自动发送」它就自己发

### LinkedIn

**Easy Apply 求职信**

1. 打开岗位详情页，点 **Easy Apply**
2. 在弹窗里翻到有文本框的那一步（通常是 **Additional information**）
3. 场景选「LinkedIn 求职信（英文）」
4. 点 **① 生成本条话术** → 话术填进求职信框
5. 自己确认后点 Next / Submit（手动模式不会替你提交）

**加好友备注**

1. 点 **Connect** → **Add a note**，把备注框打开
2. 场景切到「LinkedIn 加好友备注（英文·300字符）」
3. 点 **① 生成本条话术**
4. 面板下方会显示字数，**超过 300 会标红**，这时点「换个说法重新生成」

## 四、面板按钮说明

| 按钮 | 作用 |
|---|---|
| **▶ 一键自动：筛完就投** | 扫本页所有岗位卡片 → 逐个读 JD → 判断 → 该投的写话术并投出去 |
| **◐ 先演练一遍** | 同上，但**不投**。先用它看清它打算投哪些 |
| **■ 停止** | 停止自动流程（等当前这条走完） |
| ① 生成本条话术 | 只处理当前页这个岗位 → 生成话术 → 按模式决定是否发送 |
| 换个说法重新生成 | 同样岗位再写一版（防重复机制会强制换句式和切入角度） |
| ② 立即填入并发送 | 用话术框里**当前**的内容（你手改过的也算）填进去并发送 |
| 复制话术 / 读剪贴板当JD | 剪贴板兜底，自动读不到 JD 时用 |
| 调试导出 | **页面改版后失效时用这个**，把页面结构复制出来发我，我就能修选择器 |

### 设置区（折叠在「筛选与连发设置」里）

| 项 | 默认 | 说明 |
|---|---|---|
| 投递门槛（匹配分 ≥） | 60 | 调高更保守，调低投得更多 |
| 每日自动发送上限 | 40 | 硬闸门，到数就停 |
| 每条最小/最大间隔（秒） | 25 / 60 | 投出去的那些之间随机等这么久，避免固定节奏 |
| 最多翻页数 | 3 | 自动模式最多翻几页岗位列表 |
| 投递判定档位 | 只投高分 | 也可选「高分+边界都投」 |
| 清空「已投过」记录 | — | 一般别点；点了可能重复投之前的岗位 |

## 五、出问题了怎么办

| 现象 | 处理 |
|---|---|
| 面板顶部小圆点是**红**的 | 本地服务没起 → 双击 `start_ai_server.bat` |
| 小圆点是**橙**的 | 服务在但自检有问题，看日志区提示（多半是 API key 或简历） |
| 「本页识别到岗位卡片 0 个」 | 不在岗位列表页，或者页面改版了 → 换到搜索结果页 / 点「调试导出」发我 |
| 「没读到岗位 JD」 | 先点开岗位详情让右侧渲染出来；仍不行就把 JD 手动粘到「JD」框里 |
| 「读不到 JD，跳过」 | 同上，日志里会指明是哪一条 |
| 「找不到立即沟通按钮」 | BOSS 页面改版了 → 点「调试导出」发我 |
| 弹安全验证 | **脚本会自动停**。你手动过验证，刷新页面即可 |
| 日志区一直是空的 | 面板里的日志是实时写的；如果完全空白而且状态是「就绪」，按 F12 看 Console 有没有 `[求职助手]` 输出 |
| 怀疑面板根本没跑起来 | 按 `F12` → Console → 粘 `document.getElementById('ai-job-helper-panel')` 回车。返回元素 = 面板在（点篡改猴图标 → 「显示/隐藏助手面板」）；返回 `null` = 脚本没执行（检查篡改猴里的脚本开关、以及扩展详情页的「允许用户脚本」是否打开） |

## 六、文件清单

| 文件 | 作用 |
|---|---|
| `boss_ai_helper.user.js` | 油猴脚本（装到浏览器里的那个） |
| `matcher.py` | **岗位筛选打分引擎**（可解释的规则 + 边界分模型复核） |
| `serve_letter.py` | 本地服务（HTTP 接口：`/health` `/letter` `/match` `/record`） |
| `start_ai_server.bat` | 一键启动上面这个服务 |
| `resume_ai.py` | 读简历 + 调 DeepSeek 生成话术 |
| `letter_variety.py` | 防重复：角度轮换 + 相似度终检 |
| `prompts.py` | 4 套场景的提示词（中文/BOSS、英文求职信、加好友备注、博士套磁） |
| `resume/` | 中文简历（BOSS 用） |
| `resume_en/` | 英文简历（LinkedIn 用） |

跑完的落盘位置（`pipeline/`）：

| 文件 | 内容 |
|---|---|
| `outbox.md` | 每条投出去的话术全文 |
| `applied.csv` | 每个岗位的结果：分数、判定、状态、理由、链接 |
| `skipped.csv` | 只记跳过的岗位，想复核「是不是误杀了」看这里 |

## 七、版本记录

### v2.0.0：加「自动筛选 + 自动投递」

把「一个个点」变成「点一下就完事」。新增：

| 新增 | 说明 |
|---|---|
| `matcher.py` 筛选引擎 | 可解释打分（技能命中 + 硬排除 + 资历/学历/签证/地区扣分），边界分交模型复核 |
| `POST /match` | 脚本把「标题 + 公司 + JD + 卡片摘要」发给引擎，拿回 `apply/review/skip` + 理由 |
| `POST /record` | 投没投都归档：`applied.csv` / `skipped.csv`，投出去的正文进 `outbox.md` |
| 自动流水线 | 逐张卡片 → 本地预筛 → 读 JD → 引擎判定 → 写话术 → 投递 → 随机等待 → 翻页 |
| LinkedIn Easy Apply 自动走表单 | 填文本框 → 点下一步 → 到「提交」为止；遇签证类问题主动退回人工 |
| 跨天去重 | 已投岗位 ID 存在油猴存储里，刷新/关浏览器都不丢，再跑不会重复投 |
| 演练模式 | 只筛不投，先看清它打算投哪些 |

同时修掉三个真 bug（都是自测查出来的）：

| 问题 | 后果 | 修法 |
|---|---|---|
| **面板的日志框从来没接上**（`log()` 写的是 `logBox`，而面板建的元素是 `logBoxEl`，`logBox` 永远是 `null`） | 所有日志只进了 Console，面板上的日志区**永远是空的**，你根本看不到筛选理由和报错 | 建完元素后把引用接过去（`logBox = logBoxEl`） |
| 硬排除词本来要匹配「标题 + 卡片全文」 | BOSS 卡片的福利标签含「培训」「五险一金」，会误杀正经研发岗 | 收紧成**只匹配标题和公司名**，并加了回归用例锁住 |
| **LinkedIn 走 Easy Apply 时没记「今天投了几条」**（BOSS 走 `deliver()` 会记账，Easy Apply 是另一条代码路径） | **每日上限永远不触发，安全阀等于失效** | Easy Apply 提交成功后补 `bumpSent()`，并在自测里加了断言锁住 |

另外给「点开岗位卡片」加了多目标重试：先点卡片本体、不行再点里面的卡片主体容器，
**刻意不点里面的 `<a>`**（它的 href 指向详情页 URL，点下去可能整页跳走，
一离开列表页后面所有卡片就都处理不了了）。

### v1.3.1：修掉「读了 JD 但读错」

用真实领英岗位页做了一次离线自测（方法见下），查出并修掉四个问题：

| 问题 | 后果 | 修法 |
|---|---|---|
| 方案 A 的判定条件写成「标题长度 > 4 才允许模糊匹配」，而中文标题**全是 4 个字**（职位描述/岗位职责/任职要求…） | 方案 A 全程失效，只能靠 class 兜底 | 改成「文本等于标题，或只多一个小尾巴（≤12 字）」 |
| 方案 B 取的是「所有选择器里文本最长」 | 大容器最长，反而把「展开/收起」按钮文字一起吃进来，还会带上公司信息 | 改成按选择器**优先级**命中即用，正文元素排最前 |
| 页面 UI 文字混进 JD | 实测领英 JD 尾部带「Show more Show less」，发给 HR 很突兀 | 新增 `cleanJd()` 统一清洗 |
| **真面板从来没设过 id**（只在 `boot()` 里建了个带 id 的临时 div，加进去又立刻删掉） | `boot()` 的防重复守卫**恒为假**；在 Console 里用 `getElementById('ai-job-helper-panel')` 自查也**永远返回 null**（面板明明在页面上） | 给真面板补上 id，删掉临时 div 那段权宜写法 |

另外「调试导出」新增 `jdPlan` 字段，它会明确告诉你这条 JD 是**哪一档兜底**读到的。

| `test_auto_pipeline.py` | **自动流水线端到端**：合成一个领英搜索结果页（8 个岗位卡片 + 可点开的详情 + Easy Apply 弹窗），跑演练、跑自动投递、再跑一次验证去重 | `python test_auto_pipeline.py` |

`test_auto_pipeline.py` 里 `/match` 是**打到真实服务**上的（真 matcher、真规则），
只有 `/letter` 和 `/record` 用桩，避免把归档写脏。它会检查：

- 8 个岗位的判定是否和预期一致（该投的 3 个、标题级排除的 2 个、低分的 2 个、表单退人工的 1 个）
- Easy Apply 真的提交了（合成页自己记账）
- 能如实勾选的签证题（有标准答案的单选）**自动如实作答后提交**
- 无法如实作答的签证/工作许可开放题**被退回人工而不是硬投**
- 第二次运行**不再重复投**已投过的岗位
- 整个过程零 JS 报错、控制台零 SEVERE

页面结构改版后，用这几个方法能在**不碰你账号**的前提下把选择器调准。

## 九、安全边界（自己心里有数）

- 脚本**只监听 127.0.0.1**，外网访问不到；不碰你的账号密码，只做文本进/文本出
- 全自动档位的前置闸门：本地预筛 → 引擎判定 → 每日上限 → 随机间隔 →
  撞验证即停 → 已投去重。**一个都不能拆**
- 「签证/工作许可/国籍」类问题：脚本**只照实勾选 .env 里你填过的已知项**；
  凡是它拿不准、没有标准答案的（自由文本框等），**一律退回人工，绝不编造**。
  编一个答案的代价远大于少投一个岗位
- 每条话术都落盘存档：`pipeline/outbox.md`、`pipeline/applied.csv`
- 平台方对脚本自动化都有条款限制，风险你自己权衡。
  **最保守的用法**：只用「◐ 先演练一遍」筛出清单，再手动单条投
